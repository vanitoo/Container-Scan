## Описание

ContainerScan — настольное Python-приложение для распознавания и сопоставления номеров контейнеров из PDF-файлов.

Текущий основной сценарий: загрузить один или несколько PDF, выбрать область на странице, распознать контейнерный номер через OCR и сопоставить результат с данными из Excel/CSV-реестра.

Проект относится только к PDF/OCR-распознаванию и сверке данных. Он не связан с генерацией квитанций, Word-шаблонами, PDF-экспортом квитанций или почтовой рассылкой.

## Возможности

- Загрузка одного PDF-файла.
- Загрузка нескольких PDF-файлов с объединением во временный документ.
- Просмотр страниц PDF в Tkinter-интерфейсе.
- Выделение области страницы для OCR.
- Предпросмотр вырезанной области.
- OCR через Tesseract.
- Базовый и расширенный режимы предобработки изображения.
- Распознавание контейнерных номеров формата `ABC U1234567` / `ABCU1234567`.
- Загрузка реестра из XLSX или CSV.
- Сопоставление распознанных номеров с эталонными значениями из реестра.
- Сохранение результатов.
- Debug-режим с сохранением изображений областей распознавания.
- Базовая инфраструктура автообновления.

> Важно: EasyOCR и PaddleOCR пока не реализованы как отдельные движки. Сейчас они обозначены как направление развития, а рабочий OCR-движок — Tesseract.

## Установка

```bash
pipx install poetry
poetry install --no-root
```

Также отдельно должен быть установлен Tesseract OCR.

На Windows приложение ищет Tesseract по нескольким стандартным путям, включая:

```text
C:/Program Files/Tesseract-OCR/tesseract.exe
C:/Program Files (x86)/Tesseract-OCR/tesseract.exe
%USERPROFILE%/AppData/Local/Tesseract-OCR/tesseract.exe
%USERPROFILE%/AppData/Local/Programs/Tesseract-OCR/tesseract.exe
```

## Текущая архитектура

Приложение собирается в `PDFOCRApp`:

1. Создаётся общий `AppState`.
2. Загружаются настройки из `.env`.
3. Инициализируются сервисы:
   - `PDFService`
   - `OCRService`
   - `ExcelService`
   - `MatchingService`
4. Создаётся `MainWindow`.
5. GUI вызывает методы сервисов и обновляет виджеты.

Сейчас проект уже разделён на слои, но связь между слоями пока слишком сильная: часть сервисов обращается к GUI-виджетам через `state.gui` или принимает `tree_widget` напрямую. Это будет исправляться в следующих этапах рефакторинга.

## Переменные окружения

Файл `.env` может хранить координаты области OCR и шаблон распознавания:

```env
X_START=14
Y_START=280
X_END=77
Y_END=330
REGEX_PATTERN=^[A-Z]{3}U\d{7}$
```

## Текущие ограничения

- OCR заточен под контейнерные номера.
- Основной язык Tesseract — `eng`.
- EasyOCR и PaddleOCR пока не подключены как реальные движки.
- Координаты выделения частично зависят от масштаба отображения.
- В коде есть старые методы рядом с новыми вариантами.
- `AppState` содержит слишком много разнородных данных: PDF, изображения, GUI-ссылки, OCR-настройки и таблицу.
- Сервисы пока частично завязаны на Tkinter.
- Автообновление реализовано в `src/pdf_ocr_app/utils/updater.py`.
- Автотестов пока нет.

## План безопасного рефакторинга

### Этап 1. Документация и техническая инвентаризация

- Обновить README под фактическую структуру проекта.
- Зафиксировать текущую архитектуру.
- Зафиксировать ограничения и план рефакторинга.
- Не менять рабочую логику.

Статус: начато.

### Этап 2. Безопасная чистка кода

- Убрать дубли импортов.
- Удалить комментарии вида `добавляем/обновляем`, оставшиеся после ручной склейки кода.
- Убрать неиспользуемые импорты.
- Проверить Ruff.
- Не менять поведение GUI и OCR.

### Этап 3. Единая модель координат

- Ввести единый формат выделения области.
- Хранить координаты в нормализованном виде: `x1_norm`, `y1_norm`, `x2_norm`, `y2_norm`.
- Экранные координаты использовать только для отображения.
- Оставить один метод crop вместо старого и нового вариантов.

### Этап 4. Разделение GUI и сервисов

- `ExcelService` должен возвращать записи, а не обновлять Tkinter-таблицу.
- `MatchingService` должен возвращать результаты сопоставления, а не красить строки таблицы.
- GUI должен отвечать только за отображение.
- Сервисы должны быть тестируемыми без запуска Tkinter.

### Этап 5. OCR engine architecture

Планируемая структура:

```text
src/pdf_ocr_app/services/ocr/
├── base.py
├── tesseract_engine.py
├── preprocessing.py
├── easyocr_engine.py
└── paddleocr_engine.py
```

Сначала переносится текущий Tesseract в общий интерфейс. EasyOCR и PaddleOCR добавляются позже как опциональные движки.

### Этап 6. Тесты

Минимальный набор тестов:

- форматирование контейнерного номера;
- regex-проверка;
- загрузка XLSX;
- загрузка CSV;
- matching;
- нормализация координат;
- crop-логика на тестовом изображении.

## Разработка

Релизная сборка запускается только после создания тега скриптом:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\release.ps1 2.0.5
```

Перед запуском рабочее дерево должно быть чистым. Скрипт обновит версии в `src/pdf_ocr_app/version.py` и `pyproject.toml`, обновит
`poetry.lock`, создаст release-коммит и тег `v2.0.5`, затем отправит их в GitHub.

Проверка Ruff:

```bash
poetry run ruff check .
```

Форматирование:

```bash
poetry run ruff format .
```

После добавления тестов:

```bash
poetry run pytest
```
